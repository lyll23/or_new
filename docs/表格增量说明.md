# 本地表格增量：原始采集与研究主表之间的一层

程序读取已完整落盘的采集批次，把能够从原结构直接定位的记录写入新的 `observations.sqlite`。它不打开或改写此前封存的研究数据库，也不自动把本次数据覆盖到旧主表。**当前交付是可追溯的新增观测及逐表候选视图；基线合并尚未实现。**

## 使用

```text
python -m or_pipeline.ingest --batch 原始数据/2026/09/17/RUN_ID --database 数据表增量/observations.sqlite
```

需要逐表 CSV 时，增加 `--export-dir 一个新的空目录`。每张支持的表均有独立 CSV，附 `EXPORT.json` 的行数和 SHA。导出不会覆盖已有目录。数据量大时可直接用 SQLite 视图。SQLite 中数值投影采用 TEXT，以免大整数、价格小数经 SQLite JSON 函数转成浮点数。

批次目录只读。退出码 0 的含义是“原始来源记账和候选导入执行完成”，输出 `quality_approved:false`，**不代表所有请求成功、每张表都有数据或研究质量已经确认**。输入校验失败、原件损坏、外来数据库、同 run_id 对应不同批次内容等返回非零，数据库事务回滚。同步端保存执行回执，不向原始批次写文件。

## 每张表能得到什么

| 既有表 | SQLite 视图 | 本版范围和选源规则 |
|---|---|---|
| 模型每日调用明细 | `v_table1_daily` | 模型活动 JSON 的 `data.analytics`，或经过精确同对象 query/cache 绑定的模型 HTML 日行；所有窗口中的原日行都保留，不截两天。这里只是候选。 |
| 每日明细的筛查后增量 | `v_table1_daily_increment` | 身份、显式版本、日期、三核心整数和同对象缓存通过机械筛查，且同一完整逻辑键没有原值修订；相同值重复来源按稳定 ID 引用一条。仍需与旧表身份、窗口、冲突交叉核查，不能直接当最终主表。 |
| Market Share | `v_market_share` | 原 `x/ys` 整期向量；单位未知。旧 tokens 与新文本请求份额定义不能混用。 |
| Leaderboard | `v_leaderboard` | 原向量，tokenizer 和 token 尺度未确认时不补默认值。 |
| Tools / Images | `v_tools` / `v_images` | 保留各自指标；不能换成 tokens、普通请求数或 Table1 媒体计数。 |
| Categories / Programming / Natural Languages / Context Length | `v_categories` / `v_programming_languages` / `v_natural_languages` / `v_context_length` | 请求筛选参数按大小写保存；未证明响应实际应用了筛选条件，保留待核标记。 |
| 排名历史 | `v_rankings_history` | `rankings_models` 原数组按请求 day/week/month 分开；**不当作 Table1 每日序列**。只保留原字段 `rank`，不以数组位置伪造官方排名。旧 HTML `rankMap/rankingData` 不在本版新采集解析范围内。 |
| 当前模型属性 | `v_model_attributes` | 官方目录 `data` 的原模型对象；保留历次观察，不自动选“最新就是正确”。 |
| 服务端点 | `v_provider_endpoints` | 仅明确的 `data.endpoints` 原端点对象；父模型、请求模型和端点原身份分存，不借父对象填版本。 |
| 历史属性与价格 | `v_model_attributes_history` | 引用同一批目录候选及其历次采集关系，不重复制造独立样本；旧历史原件、旧 CSV 与基线尚未合并。 |
| Audio Dashboard | `v_audio` | 原音频图向量；不认定 tokens、秒数或请求数，也不把新版音频输出和旧音频输入混作一条指标。 |
| Benchmarks | `v_benchmarks` | aaData/daData 的具名指标数组；费用排序列表只有原序号，不生成金额或评测分数。 |
| Fastest Models | `v_fastest_models` | 原 performance 向量。速度和延迟排序不各复制一份观测；单位、测量窗口待核。 |

一般图表视图不自动择源，每个 `vector_id` 保存完整实体集合。比较时应连同系列、筛选参数、单位、窗口、tokenizer、预测配置使用；不得从另一向量补入 Others 或剩余模型。不同日期标签不移动到同一周日/周一。一个日期出现一张向量不代表完整覆盖。

提供者目录、端点性能、有效价格汇总和 ZDR 原数组分别进入 `v_provider_directory`、`v_endpoint_performance_aux`、`v_effective_pricing_aux`、`v_zdr_aux`，不冒充端点 UUID、每日调用或目录报价。`rankings_page`、`rankings_discovery`、新版 `modality_chart` 及任何未识别结构保留原响应和 `extractions.issues_json`。HuggingFace 仓库表不制作，但 OpenRouter 原有 HF ID 正常保留。

## 字段、键与可追溯关系

- `batches`：run、五个入口文件的 SHA、catalog/plan 路径和采集质量原记录。
- `events`：每一次请求/重试均独立，键为 run_id + request_id + attempt；保留完整 manifest 原对象、响应路径、来源 SHA、接收时间、请求参数和 HTTP 状态。失败响应也保留，不给成功事件共享认证。
- `candidates`：原生记录 JSON、精确 JSON Pointer 或 RSC locator、全部新增字段、字段投影状态/来源路径、来源上下文、缓存证据和提取器版本。原响应全文只保存在 `.gz`，不再塞进 SQLite。
- `event_candidates`：同一正文被多次采到时的来源关联；内容与定位相同可复用候选，新的抓取事件仍保留。`event_candidate_qualifications` 逐“事件 × 候选”保存完整资格标记；视图中的 `event_quality_flags_json` 是该次采集的判断，绝不借另一次响应的时间资格。候选自身的 `quality_flags_json` 只描述原记录和同对象缓存。
- `extractions`：每个事件在每个代码版本下的解析结果及未映射问题。同步回执用 `import_signature()` 绑定 ingest、HTML 解析器及映射文件 SHA；代码升级可重读旧批次，新版本追加，旧结果不消失。
- `logical_key`：原身份命名空间、原日期/版本状态、统计系列和请求窗口上下文；不按模型别名模糊合并。`v_revisions` 显示同键出现不同原状态的情况，不判断哪次一定错误。不同原接口/窗口上下文没有已证可比关系时保留独立键。

旧解析版本继续留在一般候选视图中。`metadata.active_extractor_version` 仅在一个批次完整导入后更新；`v_table1_daily_increment` 只选这一明确版本，避免代码升级后把同一记录的两个解析版本重复计算。当前版本尚未重解析到的旧批次不会借旧版本自动进入该视图；同步工具根据代码签名重新导入本地已归档批次。数据库也有稳定的实例 UUID，删除后新建的数据库不能凭旧回执跳过导入。

所有研究视图同时提供 `raw_record_json`、`fields_json`、`evidence_json` 和原字段投影列。属性中的价格、模态、tokenizer、context、HF ID、能力和数据政策等有直接列；有同名原平面字段时即使为 null 也优先保留，不拿嵌套值掩盖，全部备选原路径保存在 evidence。`top_provider` 的限制不会升为全模型限制。

原始数值不经 float；缺失、null、空字符串和显式 0 以 field state 区别。对 JSON 语法允许的数值保留精确十进制含义；原 token 的字面拼写、空白与顺序可通过来源 SHA 和 locator 回到原响应。数组位置不是官方 rank，模型名不等于稳定目录 ID，HF ID 空值不等于闭源。

## 时间与统计边界

`observation_time` 是本次 HTTP 接收结束时间；`business_date` 仅从原记录日期标签解析，不从文件名或抓取日填补。`created`/`created_at` 是模型原属性，绝不是采集时间。`actual_archive_capture_verified=0` 表明这些新记录不是 Wayback 认证捕获；本次现场接收时间仍以 manifest 保存。

Table1 的 cachedAt 只能取同一个统计对象。原字段为明确 13 位整数时沿用已核 appStats 字段的 Unix 毫秒解释进行 UTC 日终筛查；不借相邻组件、dataUpdatedAt 或响应日期替代。不明缓存单位保留待核。UTC 缓存时间不证明业务日采用 UTC；超过日终也不能证明统计最终不再修订。当天和缓存早于日终的记录保存于候选，不进入筛查后增量视图。

API 原日期须为有效纯日期或完整午夜标签才能进入日记录筛查；非午夜时间戳不会截成日统计。原版本和模型身份须是非空、非纯空白的字符串；布尔值、数组等原值继续保存，不能因为字段“存在”就当有效版本。缓存晚于该次响应接收时间也单独留待核。原响应存在重复 JSON 键时不默取最后一个值；API 或 HTML 原行出现这种歧义时停止相应映射并保留原件问题。

`count` 不加“成功请求”限定，媒体字段不加“请求数”限定。当前官方 Performance 工具错误率的分母是 `requests_where_finish_reason_is_tool_calls`；历史 Table1 的 `total_tool_calls` 没有证明等价，程序不计算该比率。标签中的单位、窗口、forecast 配置未证明时保持未知；只有逐点显式预测标记才能说明对应点是预测，存在全图预测配置不等于全部点都预测。

## 下一步怎样与旧表合用

本版先保存原始响应、候选、修订和逐表投影，原封存表保持不变。正式追加需要另行固定一个导入批次，核对已有模型/版本命名空间、整图系列和窗口、旧键交集与跨来源冲突，再生成新的独立版本和全列 delta 验收。本版没有“自动覆盖旧表”的隐藏分支，也没有把所有公开字段均可解释或均已入表作为成功条件。

`config/table_mappings.json` 是机器可读的支持范围和语义边界；真实采集后须根据 `events_without_mapped_candidates`、逐端点问题和原响应复查结构变化。测试使用隔离临时数据库与合成响应，不请求网络、不读取旧生产库。
